# RabtaaAI — "RabtaaAI"

> *"Report a problem. We'll find who can fix it."*
> **"آپ مسئلہ بتائیں، ہم ذمہ دار ادارہ تلاش کریں گے۔"**

A production-grade, browser-based civic reporting and automated government routing platform designed specifically for Karachi citizens. Citizens can submit issues using **Photo 📷**, **Voice 🎙️**, or **Text ✍️** (in English, Urdu, or Roman Urdu). The AI understands the report, extracts location, classifies the civic disruption, maps it to the responsible government authority using deterministic database-driven jurisdiction rules, checks for nearby duplicate complaints, prepares formal bilingual complaints, and dispatches official English communications to verified authority contacts.

---

## 🌟 Key Features

1. **Multimodal Citizen Input**:
   - 📷 **Photo**: Supports mobile camera capture (`capture="environment"`), file upload, drag-and-drop, and automated EXIF GPS extraction.
   - 🎙️ **Voice**: Browser MediaRecorder API with live pulse animations, recording timer, audio playback, delete, re-record, and multilingual transcription via Whisper.
   - ✍️ **Text**: Full support for English, Urdu, Roman Urdu, and mixed speech (e.g., *"North Nazimabad Block H mein 4 din se kachra nahi uthaya gaya"*).

2. **Intelligent Location Engine**:
   - Strict priority system: Explicit Map Pin / Manual > Browser GPS (`navigator.geolocation`) > Photo EXIF GPS > Extracted Text > Geocoded Karachi fallback.
   - Interactive OpenStreetMap / Leaflet map with drag-and-drop pin placement and Karachi boundary validation.

3. **Deterministic Authority Routing Engine**:
   - **No Hallucinated Emails**: Official emails are never generated by an LLM; they are strictly retrieved from the database.
   - **KWSB / KWSC** (`info@kwsc.gos.pk`): Clean water supply, pipeline leaks, sewerage network, and sewage overflows.
   - **SSWMB** (`+92 3181030851`, Email: None): Garbage collection and solid waste. Marked as `email_pending` with clear citizen notification: *"An email contact has not been configured for this authority yet."*
   - **KMC** (`mayor@kmc.gos.pk`): Main roads, bridges, storm water drains, safari park, zoo, encroachments, fire & rescue.
   - **Cantonment Boards**:
     - Clifton & DHA (CBC): `info@cbc.gov.pk`
     - Korangi & Landhi (CBKC): `newceo.cbkc@gmail.com`
     - Faisal Cantt (FCB): `faisalcantonmentboard@gmail.com`
     - Malir Cantt (MCB): `pa.cbmalir@gmail.com`
     - Manora Cantt (MNCB): `cbmanora75@gmail.com`
   - **Town Administration** (`mayor@kmc.gos.pk`): Neighborhood streets, potholes, streetlights, and local sanitation.

4. **Multi-Factor Duplicate Detection**:
   - Checks semantic category match + geographic distance (Haversine threshold < 600m) + recent time window.
   - Enables citizens to add support to existing complaints (`report_count` increment) rather than creating redundant tickets.

5. **Bilingual Citizen UX & Official English Dispatch**:
   - Global instant language toggle (**English | اردو**) with zero LLM latency and full `dir="rtl"` layout mirroring.
   - Citizen UI displays both English and Urdu drafts.
   - Outgoing email sent to authorities is **always in formal English**.

6. **Comprehensive Complaint Dashboard**:
   - Live filtering by date (`All`, `Today`, `Last Week`, `Last Month`).
   - Real-time search across categories, locations, reference IDs, and authorities.
   - Full detail view (`/complaints/:id`) with interactive map, original evidence preview, and audit milestone timeline.

## 🏛️ System Architecture

```
[ Citizen Browser ]
  ├── Photo (EXIF GPS) / Voice (MediaRecorder) / Text (English | اردو | Roman Urdu)
  └── Leaflet Interactive Map / Browser Geolocation API
       │
       ▼ (HTTP / JSON)
[ FastAPI Backend Engine ]
  ├── 1. Vision Analysis: Google Gemini (visible facts only)
  ├── 2. Audio Transcription: Groq Whisper Large v3
  ├── 3. Text Normalization: Groq Llama / Qwen
  ├── 4. Location Priority Engine: Manual > GPS > EXIF > Text
  ├── 5. Authority Routing: Database-driven rules
  ├── 6. Duplicate Detection: Haversine distance (<600m) + Category + Time
  ├── 7. Dual Complaint Generator: Formal English & Courteous Urdu
  └── 8. Dispatcher: Resend API (idempotent, official English template)
       │
       ▼
[ PostgreSQL / Supabase Schema with pgvector & RLS ]
  ├── authorities & authority_contacts
  ├── authority_jurisdictions (Cantonments & Towns)
  ├── issue_categories (14 categories) & subcategories
  ├── complaints & complaint_embeddings
  └── complaint_events (audit timeline)
```

## 🚀 Quickstart & Installation

### Prerequisites
- **Python**: 3.11+
- **Node.js**: 20+
- **npm**: 10+

### 1. Backend Setup
```bash
cd backend

# Create virtual environment (optional)
python -m venv .venv
# On Windows: .venv\Scripts\activate
# On Linux/macOS: source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Start backend server
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```
The backend API is accessible at: `http://127.0.0.1:8000`
Interactive API Docs (Swagger): `http://127.0.0.1:8000/docs`
Health check: `http://127.0.0.1:8000/api/health`

### 2. Frontend Setup
```bash
cd frontend

# Install dependencies
npm install

# Build for production
npm run build

# Start development server
npm run dev
```
The application opens at: `http://127.0.0.1:5173`

## 🌐 Full Cloud Deployment Guide

### 1. Deploy Database on Supabase
1. Open your Supabase Dashboard: [https://supabase.com/dashboard](https://supabase.com/dashboard).
2. Go to **SQL Editor** -> **New Query**.
3. Copy the entire contents of [`supabase_complete_schema.sql`](./supabase_complete_schema.sql) and click **Run**.
4. All tables (`authorities`, `complaints`, `complaint_events`, `issue_categories`), RLS policies, and seed data will be created instantly.

### 2. Deploy Backend on Render
1. Create a new Blueprint from `https://github.com/fahad15fede/RaabtaaAI.git`.
2. Render reads the root `render.yaml` and creates the backend web service.
3. Add the values from your local `backend/.env` in Render's private environment settings for keys marked `sync: false`.
4. After deployment, copy the Render service URL for `VITE_API_BASE_URL` in Vercel.

### 3. Deploy Frontend on Vercel
1. Import `https://github.com/fahad15fede/RaabtaaAI.git` as a Vercel project.
2. Set the project root directory to `frontend`; `frontend/vercel.json` configures the Vite build and SPA routes.
3. Add `VITE_API_BASE_URL` using the Render service URL, plus `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
   Never add `SUPABASE_SERVICE_ROLE_KEY` or SMTP credentials to Vercel.
